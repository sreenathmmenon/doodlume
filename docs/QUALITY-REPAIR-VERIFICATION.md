- Source-aligned platform scenes retain stationary artwork and composition. Real Meta grounding and local SAM recover complete moving subjects. Source-neighbor background reconstruction removes moving silhouettes without a black hole or duplicated actor.

- Image updates rebuild derived scenery locally before applying. Source backgrounds are protected from ordinary object edits.

## Source-object edit architecture — November 3

A fresh live Dino creation exposed a previously missed defect: editing a source platform's collider from approximately183 to350 pixels wide and y475 to430 left its visible artwork in the original backdrop. The earlier play checks did not establish that existing pictured objects could be moved faithfully.

The repair separates three things: the original complete source-art selection (`artSource`), original collision placement (`sourcePlacement` when explicitly known), and the collision baseline of an independently edited layer (`sourceLayer`). An edit prepares the old source location and its extracted layer together before it can apply. Runtime and editor preview use the same artwork transform. Undo and backup serialization retain both the artwork and baseline. Later image updates retain detached-object masks in their request context. Renaming alone makes no source-preparation request; later movement of an already detached object reuses its mask. Draft preview caches preparation by detached object identities and gate connections, rather than every drag position.

Legacy terrain can contain only a narrow landing lip. Local Meta SAM2.1 recovers its whole anchored source object when needed; a failed recovery keeps the draft unapplied. No remote provider is called for that step. In the saved real Dino result, SAM recovered the green top and purple supporting block, and the requested350px surface now has350px of visible artwork at y430. A local pixel composite was inspected; this is not a claim of browser gameplay verification. Background reconstruction can still leave subtle texture differences.

New generation requests complete visual bounds separately from a walkable ledge. The first live attempt exposed over-strict optional-bound validation and failed after about93seconds. That rejection was removed: small disagreements use a bounded visual union; uncertain optional bounds are omitted without rejecting otherwise valid gameplay or claiming verified full-object metadata. A fresh provider/UI retry remains required after this correction.
