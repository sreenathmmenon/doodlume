# Doodlume quality floor

The owner's current required target is 10/10 in every category, with9/10 the earlier minimum floor. A strong average cannot hide a weak category. Ratings describe an evidence-based product assessment, not an actual hackathon judge's score or a prediction of winning. Passing tests is one part of the evidence.

| Category | Evidence needed before assessing it in the 9 range |
| --- | --- |
| Source fidelity | Original image and actual extracted pixels remain recognizable; roles, regions and introduced elements are clear; failed masks do not masquerade as precise cutouts. |
| Creative control | Explicit requested supported actions survive creation; creators can change roles, requirements and clues, undo, and keep earned progress. Unsupported requests produce useful clarification. |
| Game design | A clear mission, intentional start, reachable required actions, meaningful progression and a satisfying finish. No starting reward, unnecessary duplicate objective or inaccessible required target. |
| Controls and feedback | Legible controlled character on arbitrary backgrounds; responsive keyboard/touch/pointer input; no remote activation, movement after pause, ambiguous state or collision jitter. |
| Visual craft | Consistent typography, hierarchy and spacing; artwork stays central; overlays and controls do not cover required details; no stretching or accidental source substitution. |
| Onboarding and recovery | A person can understand create, review and play without technical instructions; source and progress survive cancellation, service errors and failed edits. |
| Accessibility and responsive layout | Keyboard alternatives, clear focus, meaningful names, sufficient contrast, reachable controls, reduced motion and readable phone layouts. Physical-device and assistive-technology checks must be distinguished from emulation. |
| Performance | Actual creation latency and frame behavior measured on varied inputs. Idle states, large images, resize and repeated scenes stay bounded. A local fast build does not prove phone performance. |
| Reliability and persistence | Fresh source → model → review → play → edit → undo → save → reopen works. Generation validation and actual completed playthroughs are counted separately. |
| Privacy and model integrity | Credentials stay server-side and ignored by Git; provider use is explicit; Meta inference is real; no fabricated worlds, silent paid fallback, false precision or completion injection. |
| Delight and replay value | Strong observable interaction design plus feedback from actual people across intended ages. Effects alone do not prove attachment, retention or willingness to pay. |
| Demonstration quality | A genuine, understandable complete session, including original artwork, Meta's contribution and a same-world change; no edited video implying unsupported capabilities. |

Every release record must list the inspected inputs/flows, observed failures, fixes and remaining unverified gates. Never replace an unverified category with an invented 9/10. Implementation work takes priority over producing more review transcripts.
